    - see AuditInterceptor.cs

How do the default queries ignore the entity rows that have been soft deleted?
In FshDbContext:
    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        // QueryFilters need to be applied before base.OnModelCreating
        modelBuilder.AppendGlobalQueryFilter<ISoftDeletable>(s => s.Deleted == null);
        base.OnModelCreating(modelBuilder);
    }

The currently implemented CanBeSoftDeleted interface method
assumes that an entity of a given type is only referenced in 
a single other entity type.

To add a new entity:

Open the CSharpRanchRewriter project in Visual Studio.

Update the RewriterSpecs.cs file with the new entity name and the properties for the new entity, and a new Nav Icon spec, update the module to name

For now, in the RewriterExec, comment out 
    - the Blazor rewrites at the bottom (we will run them in just a minute).
    - the module write and clean code (see other instructions for creating a new module)

Run the CSharpRanchRewriter project.

The project will create all of the necessary files for the new entity in the WebApi,
move those files to the actual project, and then update other files in the project.

NOTE:  Rebuild the FSH project to ensure that the rewriting was successful.
If something goes wrong and the CsharpRanchRewriter needs updating, be sure to git restore the original versions of the RandomRanch files.

When this is complete, navigate to
~/Desktop/AI/randomRanch/dotnet-starter-kit/src/api/server

and run the following commands:
 dotnet ef migrations add "Add [New Entity Name] to Ranch Schema" --project .././migrations/postgresql/ --context RanchDbContext -o Ranch
 dotnet ef database update --project .././migrations/postgresql/ --context RanchDbContext

When this is complete, run the RandomRanch solution Host.  The host will launch Swagger.

Now, navigate to ~/Desktop/AI/nswag and run the following command:
 nswag run nswag.json

 This will create a new version of the ApiClient.cs file in ~/Desktop/AI/nswag.
 Copy this ApiClient.cs file to
 C:\Users\EricOwens\Desktop\AI\randomRanch\dotnet-starter-kit\src\apps\blazor\infrastructure\Api,
 replacing the existing ApiClient.cs file already there.

Now, update the CSharpRanchRewriter RewriterExec file, commenting out the code line just run, and uncommenting the
lines at the bottom that rewrite Blazor content.

Run the CSharpRanchRewriter project.

This should complete the new entity in the FSH project.

Validators applied here:
    public static WebApplicationBuilder RegisterModules(this WebApplicationBuilder builder)
    {
        ArgumentNullException.ThrowIfNull(builder);

        //define module assemblies
        var assemblies = new Assembly[]
        {
            typeof(CatalogMetadata).Assembly,
            typeof(RanchMetadata).Assembly,
            typeof(TodoModule).Assembly
        };

        //register validators
        builder.Services.AddValidatorsFromAssemblies(assemblies);

        //register mediatr
        builder.Services.AddMediatR(cfg =>
        {
            cfg.RegisterServicesFromAssemblies(assemblies);
        });

        //register module services
        builder.RegisterCatalogServices();
        builder.RegisterRanchServices();
        builder.RegisterTodoServices();

        //add carter endpoint modules
        builder.Services.AddCarter(configurator: config =>
        {
            config.WithModule<CatalogModule.Endpoints>();
            config.WithModule<RanchModule.Endpoints>();
            config.WithModule<TodoModule.Endpoints>();
        });

        return builder;
    }
